# Regional failover drill — 2026-07-10

## Result

Passed. Removing one healthy regional backend from the global edge shifted readiness, model
discovery, and synthetic inference traffic to the remaining region without an observed application
error. Restoring the backend returned the declared infrastructure to a clean plan.

## Design requirements verified

- The serving-region response header identifies which region handled a request.
- Cross-region model access is explicitly enabled where the failover design depends on it.
- Network policies admit gateway traffic from every declared failover region without publishing
  internal network ranges here.
- Regional health checks and the global edge validate the same critical serving path.
- Failback is judged by backend health and per-region request telemetry; a single client's routing
  can remain sticky after the backend set is restored.

## Repeat procedure

1. Confirm rollback authority, regional capacity, and a continuous synthetic sampler.
2. Remove one backend through the declared infrastructure workflow.
3. Verify readiness, model discovery, and synthetic inference through the public edge.
4. Restore the backend, confirm both regional paths are healthy, and check for infrastructure
   drift.

Repeat after changes to edge backends, regional capacity, gateway networks, model-service
exposure, health checks, or NetworkPolicies. Keep exact timings, resource names, routes, and raw
traffic samples in the restricted drill record.
