# Regional failover drill — 2026-07-10

## Result

Passed on the second attempt. With the us-central1 backend removed from the global edge, public traffic served from us-east4 with zero observed failed requests, and real inference completed through the public endpoint from the east gateway. The first attempt failed and surfaced two real gaps, both fixed and re-verified before this record was written.

## Gaps found by the first attempt

1. **Cross-region model access was impossible.** The internal passthrough load balancers in front of `standard-vllm` and `confidential-vllm-cpu` did not set `allowGlobalAccess`, so Google rejected connections from any client outside us-central1. The east gateway served control-plane routes but returned 504 on inference. Fix: `networking.gke.io/internal-load-balancer-allow-global-access: "true"` on both internal LB Services in `deploy/kubernetes/overlays/standard-smoke/vllm-standard-internal.yaml`.
2. **Model NetworkPolicies only allowed the us-central1 range.** Internal passthrough load balancers preserve the client source IP, so east-gateway traffic (10.30.0.0/24) would have been dropped at the pod even with global access enabled. Fix: added 10.30.0.0/24 to both vLLM ingress NetworkPolicies.

A failover design that has not been drilled should be assumed broken; both defects were invisible to per-region health checks because each region was individually healthy.

Failback routing note: after re-attaching us-central1, Google Front End routing continued to prefer us-east4 for the drill client for over twenty minutes even though both backends were attached and healthy. Cloud Run request logs confirmed failback at the platform level during the same window: both `sovereign-api` and `sovereign-api-secondary` were serving public `https://api.opensoftware.co/readyz` requests with 200s (the global uptime checkers reach both regions). Treat "traffic returns to the nearest region" as eventually consistent and judge failback by the attached backend set and per-region request logs, not by which region serves a given client.

## Verification checklist used

1. `x-gateway-region` response header identifies the serving region on every response.
2. Readiness (`/readyz`) polled at 5-second intervals across the failover window, recording HTTP status and region.
3. `/v1/models` and three real `/v1/chat/completions` requests through the public domain while only the east backend was attached.
4. East service ingress and IAM restored to `internal-and-cloud-load-balancing` + public invoker after the direct pre-drill probe.
5. `terraform plan` clean after restore (no drift, both backends declared and live).

Repeat this drill after any change to the edge backend set, gateway subnets, model service exposure, or NetworkPolicies, and at least quarterly alongside the Firestore restore drill.
