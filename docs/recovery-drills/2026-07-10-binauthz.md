# Binary Authorization enforcement drill — 2026-07-10

## Result

Passed. Admission enforcement rejected unsigned or otherwise unauthorized images while admitting
signed release images. Existing healthy workloads remained available because the policy is
evaluated when a new workload is admitted.

## Control tested

- The default policy denies untrusted application images.
- Platform-maintained system images use narrowly scoped exemptions required for managed cluster
  operation.
- Application images must carry an attestation from the release signing identity.
- Enforcement covers both container-orchestrated model workloads and serverless gateway releases.

The drill attempted an unauthorized deployment in an isolated test path, confirmed admission was
denied without replacing the healthy revision, then deployed an authorized release and confirmed
normal readiness. A clean infrastructure plan verified that the temporary test state was removed.

## Multi-architecture signing note

Different runtimes can evaluate different OCI digests: one may inspect the multi-platform index
while another inspects the resolved platform manifest. The release pipeline therefore signs the
index and every deployable platform manifest. Retained rollback artifacts must remain signed too.

Repeat after changes to the admission policy, attestor, signing key, image registry, release
workflow, runtime platform, or rollback-retention policy.
