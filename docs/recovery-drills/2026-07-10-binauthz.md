# Binary Authorization enforcement drill — 2026-07-10

## Result

Passed. The project Binary Authorization policy denies every image that is not in the explicit allowlist, and enforcement is active on the inference GKE cluster and all three gateway Cloud Run services. Running workloads were unaffected (admission-time control only).

## Policy shape

- Default admission rule: `ALWAYS_DENY` with `ENFORCED_BLOCK_AND_AUDIT_LOG`.
- Allowlist: the project's `sovereign-inference` Artifact Registry repository and `docker.io/vllm/*` (the pinned model server images; manifests reference them by digest).
- Google-maintained GKE system images are exempted via the global policy so cluster upgrades keep working; nothing user-deployed is exempted.
- Enforcement is opt-in per workload: the `sovereign-inference` cluster uses `PROJECT_SINGLETON_POLICY_ENFORCE` and the `sovereign-api`, `sovereign-api-secondary`, and `sovereign-api-canary` services use the default project policy. The unrelated `centaur` cluster in the same project is not affected.

## Verification

1. **GKE denial**: `kubectl run --image=nginx:1.27` in the `inference` namespace was rejected at admission: `Image nginx:1.27 denied by Binary Authorization default admission rule. Denied by always_deny admission rule`.
2. **Cloud Run denial**: deploying `nginx:1.27` to the canary service failed: `is not authorized by policy ... Denied by an ALWAYS_DENY admission rule`. The service kept serving its previous healthy revision.
3. **Authorized path**: redeploying the production gateway digest from the project registry succeeded immediately afterward.
4. `terraform plan` clean after the change; the serving model pod was untouched throughout.

## Notes

- This is the pattern-allowlist tier of supply-chain control. Attestor-based signature verification (CI signs, policy requires the attestation) is the follow-on hardening.
- The model rollout drill's "broken image" step previously used `registry.k8s.io/pause`; under this policy such an image is now denied at admission rather than failing readiness — the rollback behavior of `scripts/model_rollout.sh` is unchanged (the rollout stalls and is undone).
