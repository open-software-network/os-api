# Capacity saturation test — 2026-07-10

## Result

Passed. Gateway 0.7.0 enforces per-backend admission control globally through Redis. With `max_concurrency: 8` configured for the confidential CPU backend, a burst of 24 concurrent long-generation requests against the private canary produced **exactly 8 HTTP 200 responses and 16 HTTP 503 responses** — the bound held precisely across concurrent gateway instances — and a single request issued immediately after the burst succeeded, confirming capacity fully recovers.

## Overload response contract

Verified live while capacity was held by 10 background requests:

```
HTTP/2 503
retry-after: 10
{"error":{"message":"The model is at capacity; retry after a short delay",
  "type":"server_error","param":null,"code":"model_overloaded"}}
```

- Rejection happens **before** any billing reservation, so overload never creates wallet charges or usage records.
- The in-flight counter is released on every exit path: success, streaming completion, upstream timeout, upstream connection failure, upstream 4xx/5xx, and billing rejection (unit-tested; streaming release verified after the stream is fully consumed).
- The Redis key (`inflight:<backend>`) refreshes a 900-second expiry on each admit — above the 600-second upstream read timeout — so counts leaked by a crashed gateway instance self-heal rather than permanently shrinking capacity.

## Alerts added

- `model_overloaded` rejections sustained above 30/minute for five minutes.
- Model-backend timeouts or connection failures above 5/minute for five minutes.
- Gateway instance count at or above 80% of its Cloud Run ceiling for ten minutes.

## Scope notes

- `max_concurrency: 8` for the single CPU model pod is a starting point sized from smoke-scale usage; re-measure saturation before raising it. Raising the limit without adding model capacity converts fast 503s into slow queueing.
- Reserved or diversified GPU capacity remains open on the parity checklist; the admission control here protects whatever capacity exists, it does not create more.

Rerun this test after changing `max_concurrency`, Redis topology, model replica counts, or the gateway's upstream timeout.
