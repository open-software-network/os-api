# Capacity saturation test — 2026-07-10

## Result

Passed. A concurrent request burst reached the configured per-backend limit, excess requests
received the documented retryable overload response, and capacity recovered after admitted work
completed. The bound held across concurrent gateway instances.

## Contract verified

- Admission happens before a billing reservation or usage record is created.
- Overload returns HTTP 503 with `Retry-After` and the stable `model_overloaded` error code.
- The in-flight counter is released after success, streaming completion, upstream errors,
  timeouts, and billing rejection.
- Counter expiry exceeds the longest supported upstream timeout so a crashed gateway cannot
  permanently reduce available capacity.

The drill used synthetic, non-customer prompts and checked rejection, recovery, and counter cleanup
without publishing live limits or traffic measurements.

## Scope

Admission control protects available capacity; it does not add capacity. Re-measure saturation
before changing concurrency, model replicas, instance ceilings, Redis topology, or upstream
timeouts. Alert thresholds should be derived from the deployed capacity plan rather than copied
from a historical drill.
