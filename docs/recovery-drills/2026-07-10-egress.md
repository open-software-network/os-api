# Model-pod egress restriction drill — 2026-07-10

## Result

Passed. The confidential and standard model pods can no longer reach arbitrary destinations: all egress is denied except DNS, in-cluster traffic, and HTTPS to the HuggingFace hostnames from which the servers pull weights. A compromised model server therefore cannot open an arbitrary C2 channel or exfiltrate prompts to an unlisted host.

## Controls

- `model-egress-baseline` (standard NetworkPolicy): denies all egress from `app in (confidential-vllm, standard-vllm)` except UDP/TCP 53 to kube-dns and traffic to in-cluster pods.
- `model-egress-huggingface` (GKE Dataplane V2 `FQDNNetworkPolicy`): allows TCP 443 only to `huggingface.co`, `cdn-lfs.huggingface.co`, `cdn-lfs-us-1.huggingface.co`, and `cas-bridge.xethub.hf.co`.
- Enabled via the cluster's managed FQDN network policy feature (`enable_fqdn_network_policy`) on both the us-central1 and us-east4 model clusters.

## Evidence

From inside a running `confidential-vllm-cpu` pod:

- Blocked: `socket.create_connection(('example.com', 443))` → `TimeoutError` (dropped).
- Allowed: `socket.create_connection(('huggingface.co', 443))` → connected.

Public inference stayed at HTTP 200 before and after the policy was applied; the model server was already running with cached weights, so the restriction did not disrupt serving.

The identical policy pair is applied on the us-east4 model cluster, and that cluster continued serving public confidential inference (routed via `x-gateway-region: us-east4`) after the policy was applied. The per-pod socket probe was run on us-central1; the east cluster's exec channel was temporarily unavailable right after its control-plane FQDN update, so east was validated by continued serving rather than an in-pod probe.

## Scope

- FQDN allowances are by hostname; if a model source changes, update `deploy/kubernetes/base/egress-policy.yaml` rather than widening to all HTTPS.
- The gateway runs on Cloud Run (not this cluster) with VPC egress limited to private ranges for in-VPC traffic; a full public-egress lockdown for the gateway is future hardening.

Rerun after changing model sources, the egress policy, or the cluster's FQDN feature.
