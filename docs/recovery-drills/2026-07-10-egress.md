# Model-pod egress restriction drill — 2026-07-10

## Result

Passed. Model pods could reach only the destinations required for name resolution, in-cluster
communication, and approved model-artifact retrieval. Connections to an unapproved external host
were blocked while inference remained healthy.

## Control tested

- A baseline NetworkPolicy denies model-pod egress by default.
- DNS and required in-cluster traffic are explicitly allowed.
- HTTPS access to model-artifact hosts is granted through hostname-scoped policy rather than a
  blanket internet rule.
- Equivalent controls are rendered and validated for every deployed model environment.

The verification used a disposable pod or an existing model pod with no customer request data. It
tested one approved destination and one unapproved destination, then confirmed readiness and a
synthetic inference request.

Hostname policies depend on the runtime's network-policy implementation and the current artifact
distribution path. Repeat after changing model sources, cluster networking, DNS, egress manifests,
or runtime versions. Add a narrowly scoped hostname when a source changes; do not widen the policy
to unrestricted HTTPS.
